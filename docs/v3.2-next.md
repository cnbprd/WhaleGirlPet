日期：2026-11-27  
状态：**intensity 曲线、gaze/body lean 已完成并实测；ASR 仍未动。** 本轮先补了 90 秒正常动画长跑，再做可选姿态层，没有为了“继续”硬开新功能。

## 1. intensity 曲线

目标：情绪强度不要单帧跳变，进/出有短包络；渲染侧只消费归一化强度，不反向依赖业务语义。

**已完成（2026-11-27）**：

- 协议字段落地为 `curve: {"attack_ms": 180, "release_ms": 420}`，两个字段都可选，缺省 180 / 420 ms，夹在 40–2000 ms。
- 草案里的 `hold_ms` 没有实现：保持期由 Python 侧 `P_USER/P_LLM/P_AUTO` 的 TTL 和 TTS 播放期延长负责，渲染侧再加固定 hold 会叠两层。
- `emotionCurrent` 按 `dt / duration` 线性逼近目标；`draw()` 用 neutral 帧 0 与 smile 帧 2 按 `emotionCurrent` 混合。强度 0.8 是 80% 的笑，不是二值切脸。
- 自动眨眼优先于情绪混合；强度回到 0 时清 `emotionActive`，不残留覆盖。

验收结果：

- 0→0.8：trace 反推约 **182 ms**（设定 180 ms）。
- 0.8→0：trace 反推约 **353 ms**（满程 420 ms 的 80% 应为 336 ms，差值来自 34 ms 采样间隔）。
- 60 ms 中间帧与 neutral / happy 的全窗 RGB 平均差分别为 **0.117 / 0.414**，说明不是硬切。
- `tools/test_emotion_bridge.py` 8/8 通过，新增 `curve` payload 断言。
- 产物：`docs/_3d_emotion_neutral.png`、`_crossfade.png`、`_happy.png`、`_release.png`、`_after.png`；step 4 exe **1,324,544 B**，SHA256 `5D909D8B2F82BB65AF8966F623C0BFEFA18E86DF07D5F300D8E828DE24345119`。

正常动画长跑（2026-11-27，`3d/tools/emotion_longrun.py`）：

- 不设置 `WHALE3D_FREEZE`，`WHALE3D_FACE=auto`、`WHALE3D_CLIP=idle`，每 8 秒 `happy 0.8` → `neutral 0`，共 90 秒。
- `alive_after_90s=True`；动画前后帧平均差 **0.284**；RSS **67.5 MB** 稳定（首样本 67.9）；CPU **33.4–36.9%**；FPS **25.4–28.9**，平均 **27.76**。
- 这只证明 90 秒、单一 idle 和自动眨眼可用；没有做 24 小时浸泡，也不把它当成内存泄漏结论。

## 2. gaze / body lean

目标：让视线和身体倾斜变成“可选表现层”，不是每帧强制 IK；没有目标时回正。

**已完成（2026-11-27）**：

```json
{"gaze": {"x": 0.8, "y": -0.1, "weight": 1.0},
 "lean": {"x": 0.8, "y": 0.0, "weight": 0.8}}
```

- `EmotionBus::Frame` 增加 `gazeX/gazeY/gazeWeight`、`leanX/leanY/leanWeight`；嵌套对象存在但缺 `weight` 默认 1.0，对象完全缺失 weight=0；`x/y` 夹 [-1,1]，weight 夹 [0,1]。
- `Model::applyGazeLean()` 存目标；`applyPoseOffsets()` 在 ozz `SamplingJob` 后、`LocalToModelJob` 前改 head/neck/spine/chest 的局部四元数；`applyPoseOffsetsSelf()` 在自研采样后、`computeGlobals()` 前改节点旋转。
- 骨骼映射从 `buildOzz()` 记录：`head=5 neck=4 spine=2 chest=3`。gaze 最大 yaw 0.38 rad、pitch 0.26 rad，neck 35% / head 65%；lean 最大 roll 0.18 rad、pitch 0.12 rad，spine/chest 各 50%。
- 不带 `gaze`/`lean` 的新包 weight=0，等于回正；当前即时切换，没有平滑/回正包络。
- `3d/tools/pose_accept.py` 冻结动画抓 neutral/gaze/lean/reset；`send_emotion.py` 增加 `--gaze-*` / `--lean-*` 参数。

验收结果：

- 默认 ozz 全窗 RGB 平均差：neutral→gaze **0.948**、gaze→lean **1.330**、neutral→lean **1.600**；空 pose 后 neutral→reset **0.641**，肉眼近似 neutral，但残差没有完全解释。
- 自研 self 路径：neutral→gaze **0.809**、neutral→lean **1.336**、neutral→reset **0.648**；截图 `docs/_3d_pose_self_gaze.png`、`_3d_pose_self_lean.png`。
- 日志 `Pose bones: head=5 neck=4 spine=2 chest=3`；默认路径截图 `docs/_3d_pose_neutral.png`、`_gaze.png`、`_lean.png`、`_reset.png`。

限制：`gaze` 只转 head/neck 骨，没有眼骨或 BlendShape，视觉上接近“转头”而不是严格“转眼”；pose 未做时间平滑；90 秒长跑未叠加 gaze/lean。

## 3. ASR

目标：语音转写是**输入层**，不塞进渲染循环；识别结果走文本/情绪事件，渲染侧只收结果。

建议拆成：

- `app/asr_service.py`：麦克风/音频帧 → 文本 + 置信度；
- 文本进入现有聊天/情绪总线，不直接操作 3D；
- 默认关闭，显式开启才录音；不把音频上传到第三方，除非用户明确配置。

验收：

- 无麦克风/无模型时返回 `ok=False`，不阻塞 UI；
- 识别失败不产生假文本；
- 录音开关关闭时零采集；
- 3D 侧只验证“收到文本后表情/口型变化”，不验证声学模型准确率。

## 顺序与门

1. intensity 曲线（done：协议 + 线性包络 + 真实窗口采样 + 90 秒长跑）
2. gaze/body lean（done：可选表现层 + 双采样路径 + 真实窗口截图；长跑未叠加）
3. ASR（独立服务，最后接；未开始）

每步都要有：单元测试或可复现脚本、真实窗口截图/采样、失败回退。没有这三样就不算完成。
