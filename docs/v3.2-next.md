# v3.2 后续路线：intensity 曲线、gaze/body lean、ASR

日期：2026-11-27  
状态：**路线与验收计划，未改 3D 代码。** 本轮没有为了“继续”硬开新的 3D 功能。

## 现有协议入口

- `docs/3d-emotion-bus.md`：情绪消息/优先级/回落
- `docs/3d-transition.md`：换模过渡与验收
- `3d/emotion_bus.*`、`3d/` 现有渲染入口：后续只在这两条链路上加字段，不另起一套

## 1. intensity 曲线

目标：情绪强度不要单帧跳变，进/出有短包络；渲染侧只消费归一化强度，不反向依赖业务语义。

建议字段（草案，未实现）：

```json
{
  "emotion": "happy",
  "intensity": 0.8,
  "curve": {"attack_ms": 180, "hold_ms": 600, "release_ms": 420}
}
```

验收：

- 同一情绪 0→0.8→0，采样曲线无大于 0.15/帧的跳变（以 60 FPS 采样）；
- `release_ms` 结束回到基线，不残留表情；
- 缺省 `curve` 时按旧行为，不能破坏现有 TTS 同步。

## 2. gaze / body lean

目标：让视线和身体倾斜变成“可选表现层”，不是每帧强制 IK；没有目标时回正。

建议字段（草案）：

```json
{"gaze": {"x": 0.3, "y": -0.1, "weight": 0.6},
 "lean": {"x": 0.2, "weight": 0.4}}
```

验收：

- `x/y` 归一化到 [-1, 1]，越界截断；
- 视线只转眼/头，不带动整模位移；`lean` 只做小角度倾斜，不破坏点击穿透；
- 关闭开关时完全回正，不残留偏移；
- 与现有窗口透明/置顶/点击穿透不冲突。

## 3. ASR

目标：语音转写是**输入层**，不塞进渲染循环；识别结果走文本/情绪事件，渲染侧只收结果。

建议拆成：

- `app/asr_service.py`：麦克风/音频帧 → 文本 + 置信度；
- 文本进入现有聊天/情绪总线，不直接操作 3D；
- 默认关闭，显式开启才录音；不把音频上传到第三方，除非用户明确配置。

验收：

- 无麦克风/无模型时返回 `ok=False`，不阻塞 UI；
- 识别失败不产生假文本；
- 录音开关关闭时零采集；
- 3D 侧只验证“收到文本后表情/口型变化”，不验证声学模型准确率。

## 顺序与门

1. intensity 曲线（只改协议 + 渲染插值，风险最低）
2. gaze/body lean（只加可选表现层，先关后开）
3. ASR（独立服务，最后接）

每步都要有：单元测试、真实窗口截图/采样、失败回退。没有这三样就不算完成。
