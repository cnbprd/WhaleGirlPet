## 一、不只换皮肤：协议真的接上了

`app/api_access.py`（新）把三家协议收成一套：

| 协议 | 对话 URL | 认证头 | system 放哪 | 回复取值 |
|---|---|---|---|---|
| OpenAI 兼容（智谱/DeepSeek/Moonshot…） | `{根}/chat/completions` | `Authorization: Bearer` | messages[0] | `choices[0].message.content` |
| Anthropic | `{根}/v1/messages`（填 /v1 也能补对） | `x-api-key` + `anthropic-version` | 顶层 `system` | `content[].text` 拼接 |
| Gemini | `{根}/v1beta/models/{模型}:generateContent?key=` | 无（key 在 query） | `systemInstruction` | `candidates[0].content.parts[].text` |

`ChatWorker` 改为按 `api_format` 走上面这套；`_chat_cloud` 与「测试连接」都把当前档的格式传进去。

## 二、高级设置三项不是摆设

| 项 | 实际生效方式 |
|---|---|
| 代理 | `urllib` 的 `ProxyHandler({"http","https"})`，整条请求走代理 |
| 自定义请求头 | JSON 解析后逐条 `add_header`（如 `{"X-Title":"whale"}`） |
| 参数覆盖 | JSON 解析后 `body.update(...)`，例如 `{"top_p":0.9}` |

JSON 不合法就忽略，不影响正常对话；保存时会提示"不是合法 JSON"。

## 三、实测

**协议层** `tools/test_api_access.py`（用本机临时 HTTP 服务当假厂商）：**21 项通过**
- URL 补全不重复（根地址/已带路径/**/v1** 三种填法）
- 三家的头与 body 结构逐项核对
- 三种回复解析 + 空返回不炸
- 模型列表：OpenAI `GET /models` → 2 个；Gemini `v1beta/models` → 去 `models/` 前缀 → 2 个；Anthropic 明确报"不支持"，提示手填；无 key 直接拒绝

**端到端** `tools/test_chat_worker_formats.py`（真发 HTTP）：**5/5 通过**
- openai → 「你好呀」、anthropic → 「我是 Claude」、gemini → 「我是 Gemini」
- 自定义头 `X-Title` 出现在服务端收到的头里；`top_p: 0.9` 出现在 body
- 无 key → `failed("no_key")`

**界面** `tools/shot_api_card.py` / `tools/shot_settings_v315.py`（离屏截图）
- 药丸互斥：点 Gemini 后 `{openai:False, anthropic:False, gemini:True}`
- 眼睛：开启后 `echoMode == Normal`
- 保存：名称/格式/模型写回配置，`connected` 置 True，`save_config` 1 次
- 断开：清空 Key，`connected=False`，其余字段保留
- 设置页：新卡片在、旧下拉不在（`hasattr(panel, "cb_profiles") == False`）

## 四、兼容与迁移

旧配置只有 `name / endpoint / model / api_key`，读的时候 `setdefault` 补 `api_format="openai"`、`models=[]`，
老用户打开不会丢配置、也不会报错。原来那套 `ed_profile_name / ed_endpoint / ed_model / ed_key`
控件的引用已全部改到卡片，`save_ai_settings` / `test_ai_connection` 也改成读卡片。

## 五、说清楚的限制

1. **没用真 key 打过真厂商**：本机没有 OpenAI/Anthropic/Google 的凭据，只能保证"结构、头、解析"对；真连一次才知道对方有没有额外要求（比如某些中转站要求 `X-Api-Key` 而不是 Bearer）。
2. **Gemini 的 key 在 URL query 里**：这是 Gemini 官方接口的既定方式，但会进代理/日志，介意的话别在 Gemini 档挂共享代理。
3. **Anthropic 不支持拉模型列表**：界面会明说"请手动填写"，不假装能拉。
4. 一张卡片同时承担"列表 + 配置"，档位多于 4 个时列表会占掉不少纵向空间，暂时没做滚动。
5. 「已连接」是保存时按"有 Key + 有地址"推断的，真正的连通性要你点一次「测试连接」。
