# 鲸鱼娘桌宠 v3.0.9：本地模型调配机制

一句话：本地模型调用从「一个请求一把梭」改成「有调度、有降级、有自愈」，同时把容易踩坑的「只用 Ollama」选项去掉了。

## 改了什么

### 1. 请求串行调度
引擎只开 1 个 slot（`-np 1`），以前聊天和指令解析两路同时打进来会互相抢 slot，后到的经常等到超时。现在所有本地请求都走 `dispatch()`，同一时刻只放一个，其余排队。
实测：两路并发 → A 1.0s 答「你好」、B 2.1s 答「再见」，总 2.1s，全部成功。

### 2. 模型自动降级
启动时按「你指定的模型 → 内置首选 → 其余按体积升序」挑候选；同名同体积的副本不重复试，避免白等。首选模型起不来（内存不足、文件损坏）会自动换下一个。
实测：故意放一个坏 gguf → 提示「`_bad.gguf` 加载时进程退出」→ 自动改用 `qwen35-4b-Q4_K_M.gguf`，7.2 秒起来并正常对话。

### 3. 端口自适应
配置端口被别的程序占用时，自动顺延找空闲端口，不再出现「本地模型连不上」其实只是端口冲突。
实测：先占住 8099 再启动 → 自动改用 8085，health 通过。

### 4. 失败自愈
进程活着但 `/health` 不通（显卡上下文被回收、端口被抢）也算不可用，自动重启一轮再答。
实测：kill 掉引擎进程 → 检测到不健康 → 自动重启并答出「重启」，8.1 秒。

### 5. Ollama 健康预检
`ollama_runtime_ok()` 零成本检查 Ollama 的 `llama-server.exe` 还在不在（60 秒缓存）。缺了就判定 Ollama 不可用，「自动」不再每次都先白打一次 500 再退回。
实测本机：`/api/tags` 正常（alive=True），但运行库缺失 → 自动直接走自带引擎，状态行显示「Ollama：运行库缺失，已自动跳过」。

> 你本机 Ollama 0.40.16 的 `llama-server.exe` 确实是缺的，想恢复 Ollama 得重装它；不重装也能照常聊天，自带引擎不受影响。

### 6. 去掉「只用 Ollama」
模型页的「本地推理后端」现在只有两项：
- 自动（有可用的 Ollama 就用，坏了/跑不动自动退回自带引擎）
- 只用自带引擎 dafeiyu（不经过 Ollama，推荐）

老配置里存着的 `ollama` 值会一次性归一成 `auto`，不会再出现「选了 Ollama 却一直报错」的死路。

### 7. 调度状态一行看全
模型页新增状态行：当前模型、端口（是否自动换过）、是否正在推理、降级说明、上次错误、Ollama 状态。鼠标悬停有调配机制说明。
实测输出：`引擎：已加载 · qwen3.5-4b.gguf · 端口 8085（自动换的） · 降级：首选 _bad.gguf 起不来，已自动换成 qwen3.5-4b.gguf · Ollama：运行库缺失，已自动跳过`

## 升级建议
直接覆盖安装即可。配置会自动迁移，模型文件不用动。云端 API 功能完全保留，本地失败仍会自动转云端。
