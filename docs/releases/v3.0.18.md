# 鲸鱼娘桌宠 v3.0.18：onedir 打包（启动快 6 倍、内存省一半）+ 本地视觉真的接上了

这版做了两件事：打包形态换成 onedir；把 Gemma 4 E2B 的多模态投影补上，右键菜单里能让她看屏幕。

## 一、onedir：启动 4.55s → 0.76s，常驻 170MB → 83MB

上一版说过 onefile 的代价：每次冷启动都要把 64MB 解到 `%TEMP%` 再执行。这版改成 onedir（`COLLECT`），exe 只留 4.4MB 引导，其余就地加载。

同一口径实测（`tools/measure_boot.py`，14 秒观察，就绪 = 内存涨到本次峰值 75%）：

| 指标 | v3.0.16 onefile（69.4MB） | v3.0.18 onedir（4.4MB exe + 147.6MB 目录） | 变化 |
| :-- | --: | --: | --: |
| 进程出现 | 0.01 s | 0.01 s | — |
| 解包子进程起来 | **4.35 s** | 无此环节（0.85 s 是短暂辅助进程） | 省掉 |
| 内存到 75% 峰值 | **4.55 s** | **0.76 s** | **−3.79 s（约 6 倍）** |
| 常驻 RSS | 170 MB（2+1 进程） | **83 MB**（1 进程） | **−87 MB（−51%）** |

配套改动：

- `WhaleGirlPet.spec`：`EXE(..., exclude_binaries=True)` + `COLLECT(...)`。
- `installer\whale_pet.iss`：`[Files]` 从「单个 exe」改成递归整个 `dist\WhaleGirlPet\`。
- `.github\workflows\release-assets.yml`：portable 改为把 `dist\WhaleGirlPet\*` 铺到包根。
- `build.ps1`：`--onefile` → `--onedir`。
- 自动更新链路不用改：它下载的仍是 `Setup-*.exe`，安装器负责覆盖整目录。

代价：安装目录里会多出 `_internal\`（约 143MB 的 dll/pyd），卸载仍由 Inno 的 unins 统一管理。

## 二、本地视觉：mmproj 到位，`input_modalities` 从 text 变成 text+image+audio+video

之前 `runtime\models` 里 `*mmproj*` 是 0 个，`gemma4-e2b-it.gguf` 只能跑文本。这版补上了配套投影：

- 文件：`runtime\models\mmproj-gemma4-e2b-f16.gguf`，940.0 MB（985,654,080 字节，与 HF `unsloth/gemma-4-E2B-it-GGUF` 的 `mmproj-F16.gguf` 完全一致），国内走 ModelScope 同文件（实测 29.8 MB/s）。
- 引擎参数：`--mmproj <file> -mmdev none`（`local_llm._spawn_and_wait`，仅在找到配套投影时加）。
- 自动匹配：`mmproj_for(model)` 先看 `config["llm_mmproj"]`，再在同目录按模型名主干（`e2b`）匹配 `mmproj*.gguf`，找不到就不加参数 —— 对纯文本模型零影响。

服务端自报（加载后查 `/v1/models`）：

| 状态 | input_modalities |
| :-- | :-- |
| 没有 mmproj（v3.0.17） | `['text']` |
| 有 mmproj（v3.0.18） | **`['text', 'image', 'audio', 'video']`** |

## 三、怎么用

托盘右键 →「看看我屏幕上是什么」。

- 截图走 `app\vision.py`：`grabWindow(0)` → 长边缩到 **512** → JPEG q80（约 40~50KB）→ base64 data URL。
- 消息结构：`{"role":"user","content":[{"type":"text",...},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}]}`。
- 角色走 `fast`（Gemma 4 E2B），切过去约 4.7s，看图一轮 1.7~10s。

## 四、踩到并修掉的 4 个坑（都是实测撞出来的）

1. **PNG 原图会被引擎 400 拒收**：2.42MB 的 PNG 直接失败；同一张转 JPEG 95KB 就通过。→ 全部转 JPEG。
2. **960px 也会 400**：data url 到 156KB 就挂，512px（48KB）稳定通过。→ `MAX_SIDE=512`。
3. **`image_url` 必须是对象**：写成字符串 `{"image_url": "data:..."}` 会 500 `Invalid base64 value`。
4. **消息结构别套错**：`vision_message()` 返回的是整条 message，不能再塞进 `content`（塞错了就是那个 `Expected 'content' to be a string or an array` 的 400）。另外，带图请求会强制锁死自带引擎（`_force_local`），因为 Ollama 的 `/api/chat` 用 `images` 字段、格式不同；角色切换后重启引擎也会沿用 `active_role`，不会又掉回 4B 文本模型。

## 五、它到底能干什么、不能干什么（实测，别高估）

- 能：看出「这是网页/文档/终端/一堆按钮」「屏幕上大概在干什么」「图里是动漫人物还是界面」。
- 不能：**读清界面上的小字**。给 `docs/api_card_v315_on.png`（有「EdgeOne Makers」字样）时，512px 的回答是"带有大量空白或重复符号的界面"，没有读出标题字符串。4B 级视觉 + 512px，只够做场景级判断。
- 要精确 OCR 就得用专门工具，不要再往上抬分辨率——960px 会被引擎拒收（见坑 2）。

## 六、模型与分发

- mmproj（940MB）**不进安装包**：它和 gguf 一样属于本地权重，安装包里只有程序。已在你机器的 `F:\WhaleGirlPetApp\runtime\models\` 放了一份，与 `gemma4-e2b-it.gguf` 同目录，开箱即用。
- 换机器时：把 `mmproj-gemma4-e2b-f16.gguf` 和 `gemma4-e2b-it.gguf` 一起放进 `runtime\models` 或数据目录的 `models\` 即可，文件名不用改（按主干 `e2b` 自动匹配）。
