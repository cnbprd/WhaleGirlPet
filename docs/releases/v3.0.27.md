# v3.0.27（2026-11-26）

本版三件：① 本地模型状态口径统一为「可启动（没有加载）」；② 打工完工不再换成
通用 `happy` 脸，保持富江基础脸；③ `anim.md` 第四阶段——反馈 L0–L3 分级、
泊松节流、thinking 占位动作。

## 1. 本地模型状态

旧面板文案是「可启动（还没加载）」，和用户看到的「可启动（没有加载）」差一个字。
现在抽出 `panel.local_llm_status_text()` 统一三档：

| 状态 | 文案 |
|---|---|
| 模型已加载 | `运行中` |
| 模型文件在、但没加载 | `可启动（没有加载）` |
| 没装本地模型 | `还没装本地模型（不影响使用，聊天走云端或台词）` |

状态行仍显示 `后端 / 模型 / 端口`；这次只统一口径，不改本地模型的路由、加载或
云端兜底逻辑。

## 2. 打工完工的富江脸

`_finish_task()` 原先在 `finish_state()` 把底脸收回富江后，又调
`set_expression("happy", 3000)`。对 `default` / `jk` 皮肤，`happy` 走的是
`assets/expressions/patches/happy.png`——闭眼大笑的通用可爱脸，不是富江的冷感脸。

现在完工只走 **L2 反馈**（气泡 + 完工音），底脸保持 `finish_state()` 收回来的
`idle` 富江脸；不再调用 `happy`。聊天的正常回复仍可用 `happy`，两者分开。

## 3. `anim.md` 第四阶段

### 反馈分级（`app/feedback.py`）

| 级别 | 语义 | 表现 |
|---|---|---|
| L0 | 静默 | 只记账，不换表情、不弹气泡、不响；用于重复刺激/聊天忙线 |
| L1 | 微反馈 | 只换表情；45s 内不重复同类自主表情 |
| L2 | 普通反馈 | 表情 + 可选气泡/音效；对话回复、打工完工走这档 |
| L3 | 强反馈 | 高优先级动作 + 气泡/音效；连接失败等需要立刻被看见的事 |

`FeedbackBus.emit()` 统一走 `_speak` / `beep` / `pet.set_expression`；动作仍由
`Director` 仲裁，L2 默认 `P_AUTO`、L3 默认 `P_LLM`，不会平白抢用户直点。

### 泊松节流

`PoissonGate` 对每个事件 key 用 `1-exp(-rate*dt/60)` 做伯努利抽样，再叠
`min_gap`：

- 自主表情：8 次/分钟上限、45s 最短间隔；
- 口渴/饥饿讨要：1.2 次/分钟、180s 最短间隔，替换原来的「每 tick 50% 硬抽」；
- 用户直点/物理事件可 `force=True` 绕过。

这样反馈不会像节拍器一样均匀，也不会因为连续调用突然刷屏。

### thinking 占位

- `send_chat()` 发出后启动 700ms 延迟；700ms 内回来不占位，避免闪一下。
- 超时后 `PetWindow.begin_thinking()` 走 `Director` 的 `P_LLM` 占位：好奇表情 +
  1.2° 轻微侧倾 + 气泡「让我想一下…」。
- 回复、失败、用户动作接管时 `end_thinking()` 只释放自己的占位，不碰别的动作；
  如果当前有用户直点（P_USER 90），thinking 会被 Director 拒绝，不会抢。

## 已知边界

- 反馈级别是当前事件口径（L0 忙线、L1 自主表情、L2 对话/完工、L3 连接失败），
  并非每个旧事件都重写；后续新增事件按同一 `FeedbackBus.emit()` 接入即可。
- 泊松抽样是离散调用的伯努利近似，不是严格排队过程；优点是无需额外线程/定时器，
  代价是极端密集调用下仍受 `min_gap` 约束，但不会精确到理论到达时刻。
- thinking 占位只在聊天链路启用；定时提醒/环境播报仍走原有气泡链路。
