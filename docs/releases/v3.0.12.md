# 鲸鱼娘桌宠 v3.0.12：档 B 第一版——网格蒙皮骨骼，走路真的会屈膝

档 A 解决的是"曲线顺不顺"，这版开始解决"身子骨动不动"。但先说要紧的：

**原计划是"把立绘拆成 8–12 个部件做骨骼"，实测这条路在现有素材上走不通。**

## 一、为什么不能拆部件

素材盘点：8 套皮肤 + 萝莉形态 + 11 张表情图，全是**整张 PNG**（267×512 ~ 310×512），
没有任何分层文件（`assets/` 下没有 PSD、没有 body/hair/arm 分离图，`_matting` 里也只有中间产物）。

按解剖比例把立绘切成矩形块再旋转，实测结果（`docs/rig_proto_legs.png`）：

- 膝盖处**必然断成一截一截**：矩形边界切不出肢体轮廓，切出来的"小腿"带着大腿下缘的像素
- 裙摆下沿被整块带出：大腿一转，一段裙摆跟着飞出去
- 旋转留下的空洞露出背景，比不弯还难看

结论：**没有分层素材，"拆部件 + 蒙皮"这条路线不成立**。要真做，前置条件是人工/AI 重画分层图
（每套皮肤 × 每个形态都要拆，这才是"3–5 天"里的真实成本）。

## 二、换了个做法：不拆图，改扭网格

Live2D 的原理：不是切图，是**给整张图铺一张顶点网格**，用骨骼驱动顶点位移，
纹理跟着网格变形。皮是连续的，关节表现为局部网格弯曲，天然没有断口。

`app/rig.py`（新增，约 220 行）：

- **骨骼**：`髋_L/髋_R → 膝_L/膝_R`，大腿绕髋转、小腿再绕膝转；膝部有混合带（10px）避免硬折
- **枢轴**：全部用相对比例（`hip_y=0.586`、`knee_y=0.773`、`hip_dx=0.065`…），
  换皮肤、萝莉形态、表情图都不用重新量坐标
- **网格**：8 列 × 20 行，裙摆下沿（`leg_top_y=0.598`）以上完全不动
- **绘制**：每格拆两个三角形，用仿射矩阵贴图 + 目标裁剪；三角形向外扩 0.18px 消缝
- **缓存**：按角度四元组缓存整帧，角度不变直接复用

## 三、实测记录

**曲线外的第二个坑：坐标算错会炸成扇形。**
第一版矩阵把"目标基向量系数"直接当成了矩阵元素，渲染出来是放射状撕裂；
第二版把裁剪放在设置变换之前，裁剪被二次变换，出来是"俄罗斯方块"。
两处都修好后才是现在这张连续的皮。

**性能**（本机，offscreen）

| 项 | 实测 |
|---|---|
| `Rig.frame()`（8×20 网格，全图重算） | **10.6 ms** |
| 网格 8×20 / 10×26 / 14×32（原型脚本） | 5.6 / 8.1 / 8.7 ms |
| 完整一帧（`_tick` + 整窗 grab） | **16.0 ms**（33ms 预算内，30fps 有余量） |

**走路 A/B**（`docs/rig_walk_compare.png`，逐帧从真窗口抓 8 帧）

- 新：两条腿绕髋/膝交替，能看出抬腿相屈膝、支撑相伸直
- 旧：整段身体条带横移，腿是"整条斜着平移"，没有膝
- 接入口：`walk` / `run` / `trot` 三种步态走骨骼；`crab` / `hop` 等仍用旧 warp

**开关**：设置 → 桌宠行为 → 「走路真屈膝」（默认开，`config["rig_mesh"]`）。
关掉立刻回退旧条带 warp，方便对照。

## 四、这版明确没做到的（别指望它现在是 Live2D）

1. **只有腿**。手臂、头、裙摆、尾巴、头发都还没骨骼化——挥手还是整图转
2. **脚没有 IK**，是纯 FK：抬腿时脚会离地/轻微穿地，没有"脚掌钉在地面"的约束
3. **大幅形变会拉伸**：超过 40° 屈膝，膝盖周围皮肤明显被拉长
4. **网格纹**：缩放比例大时能看出一圈圈细纹（三角形重叠 + 抗锯齿叠加），桌宠默认尺寸下不明显
5. 裙摆是硬的：腿在裙下动，裙子不跟着摆（要做需要 spring-bone，但前提仍然是分层图）

## 五、要继续往真 2D 骨骼走，需要你拍板一件事

现在的上限是素材。两个选项：

- **A 先这样**：腿会弯了，走路像走路了；手臂/裙摆停在"整图变换"
- **B 重画分层素材**：每套皮肤拆 8–12 部件（头发/头/躯干/上臂/前臂/大腿/小腿/脚/裙摆/尾巴），
  再用真正的层级骨骼 + spring-bone 做裙摆滞后。效果接近 Live2D，但要真的画图，
  不是写代码能变出来的

我倾向先让你用手感验收这版腿，再决定要不要为分层素材投入。
