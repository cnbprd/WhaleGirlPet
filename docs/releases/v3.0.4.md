## v3.0.4

这一版治内存：之前桌宠被强杀/崩溃后，本地推理子进程会变成孤儿，实测一个 `dafeiyu-server` 独吞 **2.39GB** 内存长达 14 小时不释放，直到重启电脑。

### 根治孤儿进程
- 新增 Windows Job Object 绑定（`app/proc_guard.py`）：子进程绑进一个 `KILL_ON_JOB_CLOSE` 的 Job，父进程一死（崩溃、任务管理器强杀、断电重启）系统自动连子进程一起收尸。
  - 实测：父进程 `os._exit(1)` 硬退后 2 秒，`dafeiyu-server` 已消失，无残留。
- 启动时清理残留（`local_llm.kill_stray_servers()`）：装新版第一次启动会把上一次留下的推理进程杀掉。实测杀掉 1 个残留进程。

### 空闲自动卸载（省 2.3–4.6GB）
- 本地 4B 模型加载后实测常驻 **4.6GB 工作集（其中私有 2.35GB）**。现在闲置超过 **20 分钟**自动停掉引擎，把内存还给系统；下次聊天自动重新加载（实测 6–8 秒）。
- 设置 → 自定义模型 新增「空闲自动卸载：__ 分钟」下拉，范围 0–240，**设 0 = 从不卸载**（想要秒回的人选这个）。默认 20 分钟。
- 只有面板开着时才提示"我先卸载腾内存"，平时静默。

### 引擎参数
- 加 `-np 1`（单 slot）：桌宠只会有一个对话请求，4 个 slot 白占 KV 内存。实测 RSS 从 4647MB → 4492MB。试过 KV 量化 `q8_0`（再省 57MB）但收益小、有兼容风险，没采纳。

### 主程序
- 聊天历史改为流式读取（只留最近 240 条在内存），不再把整个 jsonl 读进内存。
- 冷启动、不打开面板时：主进程 **95MB**（onefile 引导进程 8.6MB 另算），面板关闭状态下不常驻本地模型 → 引擎 0MB。
