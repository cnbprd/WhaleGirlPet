# 鲸鱼娘桌宠 v3.0.16：三层记忆（Core / Recall / Archival）

先纠正一个前提，再落地代码。

## 一、那段「OpenAGI 最契合」的分析，有硬伤

我把 OpenAGI 查了一遍（arXiv 2304.04370 / NeurIPS 2023 Datasets & Benchmarks，仓库 `agiresearch/OpenAGI`）：

- 它做的是**「LLM 当控制器，去选择并执行领域专家模型」+ RLTF（用任务结果做反馈来改进 LLM）**，
  外加一批基准任务、数据集和评估脚本。定位是**研究/评测平台**。
- **没有**常驻守护进程，**没有** `~/.openagi/`，**没有**「Lava 三层记忆」，**没有** `curl -fsSL openagi.sh | sh`。
  「Lava」是 Intel 的神经形态框架，和 OpenAGI 无关；「三层记忆（Core/Recall/Archival）+ 记忆衰减」
  是 **Letta（原 MemGPT）** 的招牌设计。

也就是说：那段分析把 Letta 的记忆分层，按到了 OpenAGI 头上。

## 二、重排：本项目该学谁（都核过许可）

| 项目 | 许可证 | 对本项目的真实价值 |
|---|---|---|
| **Letta（原 MemGPT）** | Apache-2.0，Python，约 2.1–2.4 万 star，v0.16.7（2026-03-31） | **最高**。Core（常驻上下文）/ Recall（缓存）/ Archival（冷存+检索）三层，加"记忆会衰减、重复会压缩"——正好补本项目的短板 |
| OpenAI Agents SDK / langmem | MIT | 中等。记忆是"键值 + 向量"，没有分层语义，参考意义一般 |
| AIOS（OpenAGI 团队后继，含调度/上下文切换/内存管理） | 见仓库 | 低。那是"LLM 当操作系统管多 Agent"的玩法，本项目是单进程桌宠，用不上调度器 |
| AutoGen / MetaGPT / SuperAGI | MIT / Apache | 低。多 Agent 编排，桌宠只有一个"她" |
| OpenCog Hyperon（MeTTa / Atomspace） | 见仓库 | 低。符号推理门槛高，接进来是给桌宠装了个不会用的脑子 |
| Nezha / Cognitive Kernel-Pro / AGIX | — | 与本项目无关 |

**结论**：该学的是 Letta 的「分层 + 衰减 + 压缩」，不是某个"AGI 框架"的整体集成。

## 三、这版做了什么

新建 `app/memory_tiers.py`（组合在既有 `MemoryStore` 之上，同一 SQLite，不迁移数据）：

| 层 | 实现 | 预算 |
|---|---|---|
| Core | `core()` 拼出「她记着的 / 当前在意 / 上一件聊过的事」，**每轮直接进 system prompt** | 420 字（拼进去后整段 system 约 700–900 字） |
| Recall | 复用既有 `search()`：2-gram 倒排 + 时间衰减打分 | 3 条 |
| Archival | 新表 `archival`：又冷又老的事实移进去，需要时可 `archival_search()` | 6 条 |

三个机制：

1. **`tick_decay()` 增量衰减**：半衰期 45 天；**只按"距上次衰减的天数"乘**，
   反复开机不会把记忆叠着扣光（首次调用直接跳过，记录 `last_decay`）。
   权重 < 0.2 且 60 天没动 → 移到 archival。
2. **`compress()`**：两条事实的 2-gram Jaccard ≥ 0.6 就合并，保留权重高/内容长的，权重相加封顶 3.0。
3. **`agenda()`**：从事实和笔记里挑命中「要/想/待/记得/下次/明天/还没/欠…」的句子，
   作为**主动开口**的候选——自主行动里 50% 概率先说"鱼片，交房租这事你没忘吧？"，而不是随机碎碎念。

## 四、顺手挖出的真问题：记忆根本没数据

直接读你机器上的库（只读，没改）：

| 库 | 消息 | 事实 | 笔记 |
|---|---|---|---|
| `F:\WhaleGirlPetApp\memory.db` | 1 | **0** | 0 |
| `F:\WhaleGirlPetApp\accounts\default\memory.db` | 64 | **0** | 0 |

64 条消息、0 条事实——三层记忆再漂亮也没有米下锅。原因在 `memory.extract_facts()`：
只有 5 条模式（名字/年龄/住处/职业/喜好），而且**提问和假设句也会被抽成事实**
（"你喜欢吃什么"会被记成"喜好=吃什么"）。

这版补到 **9 条模式**（加了"叫我X""习惯""计划""宠物"），并加了两道闸：
含 `? ？ 吗 要是 如果 假如 你会 你能 你想` 的句子一律不记；值尾部"吧/啊/呢"剥掉、喜好开头"吃/喝/玩"剥掉。

实测 `tools/test_extract_facts.py`：**15/15 通过**（10 条该记、5 条不该记）。

## 五、其它改动与实测

| 项 | 结果 |
|---|---|
| 注入去重 | `core()` 负责 facts，`context_block(n_facts=0)` 只给"相关旧对话"，facts 不会重复进口两次（实测 facts=0 时返回空串） |
| 三层单测 `tools/test_memory_tiers.py` | **8/8 通过**：首次衰减跳过、200 天一次衰减归档 1 条（factor 0.0459）、紧接着再调不重复扣、压缩合并 1 条、core ≤ 预算、议程提取成功 |
| 开机行为 | `_init_memory_tiers()` 在启动与切账号时执行 decay + compress，失败静默（不拖慢启动） |

## 六、这版不做的事

1. **不让模型自己改记忆**（Letta 的 self-editing）：4B 本地模型改写记忆块极易写坏，
   先用规则化的衰减/压缩把底座稳住，等有强 JSON 约束再说。
2. **不接向量库**：仍是 2-gram 检索，零额外体积；等记忆条数上千再考虑 embedding。
3. **不引入任何 AGI 框架**：`pip install letta` 会带来一整套 agent runtime 和它自己的数据库，
   与本项目"单进程 + PySide6 + 本地 llama.cpp"不兼容；学机制、不搬代码。
