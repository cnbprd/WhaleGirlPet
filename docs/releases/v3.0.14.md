## 二、聊天输出文字乱：加一道清洗

本地小模型的输出经常带 markdown 记号、代码块、列表符号、链接，或者整句复读、空行堆叠、结尾挂个逗号。以前这些原样进气泡和 TTS，看着就是"乱"。

新增 `Controller._polish_reply()`，在 `_finish_reply()` 第一道，**气泡、聊天记录、TTS 用同一份清洗后的文本**：

| 处理 | 规则 |
|---|---|
| 角色前缀 | `assistant:` / `user:` / `AI:` / `Reply:` 开头剥掉（中文"回答："不动） |
| 代码块 / 行内代码 | 整段移除 / 去掉反引号留内容 |
| 粗体斜体、标题、列表符、引用、分隔线 | 去记号留文字 |
| 链接 | `[文字](url)` 留文字，裸 URL 直接删 |
| 整句复读 | 同一句连着 ≥3 遍折成 1 遍 |
| 空白与残标点 | 空行压成一个换行；短回复（≤100 字）换行拉平；结尾逗号顿号改句号；半截括号引号剥掉 |

实测：`tools/test_polish.py` 六类脏文本 **6/6 通过**（markdown、代码块、列表、复读、链接、空行+残标点）。

## 五、模型三档分工（评估稿，未改代码）

方案落在 `docs/model_roles_v314.md`，核心三条：

1. **不能三个模型同时常驻**：`dafeiyu-server` 单进程一次只加载一个 gguf，三个 4B 同时驻留约 7–9GB 内存。三档只能是"一个常驻模型 + 三套参数档 + 按需热切换"。
2. **分工**：Brain = Qwen3-4B-Q4（2381.6MB，最小最稳，常驻）；Tool = qwen35-4b 或复用 Brain（temp 0.1 / 180 tokens / `fmt=json`）；Fast = 本地无 vision 权重，图片一律走云端 vision 档。
3. **缺口要说清**：`send_chat` 现在只把附件路径写进文字，**没有真正把图传给模型**；`ai_profiles` 只有一个空「默认」档。这两处不补，多模态快反只是名义上的。
