## v3.0.8

这一版把 Ollama 的模型直接接进「设置 → 自定义模型」：**能联网搜它的官方库、能下载、也能把本机已有的模型直接搬过来**——全部落成标准 gguf，由自带引擎 dafeiyu 跑，全程不启动 Ollama。

### 1. Ollama 官方库接进模型仓库

「自定义模型」页新增一块：

| 元素 | 作用 |
|---|---|
| 刷新 Ollama 模型库（联网） | 抓 `ollama.com/library`，实测 **272 个**模型名 + 简介，缓存 12 小时 |
| 模型列表 | 点一个会把名字填进下面的输入框 |
| 输入框 + 查询并下载 | 写 `qwen3.5:4b` 这种「名字:tag」，程序自己去 registry 查真实下载地址 |
| 从本机 Ollama 导入 | 见第 2 条 |

下载地址不是猜的，是查 Ollama 官方 registry 的 manifest 得到的，实测：

```
GET registry.ollama.ai/v2/library/qwen3.5/manifests/4b        → 200
layers: application/vnd.ollama.image.model  2525.9 MB  sha256:a9d0a3e1…
blob 头 4 字节：GGUF
```

也就是 **registry 里的权重 blob 本身就是标准 GGUF**，下下来不需要转换，直接喂给 dafeiyu-server。下载复用原来的断点续传（`.part`），下完自动设为当前模型。

不写 tag 时程序不会替你瞎选：会把可选 tag 列出来让你决定。实测 `qwen3.5` 的 tag：

```
latest 6.6G / 0.8b 1.2G / 2b 2.7G / 4b 3.3G / 9b 6.6G / 27b 17G / 35b 22G / 122b 81G
```

### 2. 「从本机 Ollama 导入」：把已有模型搬成 gguf

读 `OLLAMA_MODELS` 环境变量（你这台是 `D:\Ollama\workspace`）下的 `manifests`，找到 `application/vnd.ollama.image.model` 那个 layer，把对应 `blobs\sha256-…` 复制成 `<名字>-<tag>.gguf`。不联网、不启动 Ollama，后台线程复制。

本机实测（已经跑过一次）：

| 模型 | 结果 |
|---|---|
| `deepseek-coder:6.7b-instruct` | 已存在同名文件，跳过 |
| `gemma4-e2b:latest` | 已导入 `F:\WhaleGirlPetApp\models\gemma4-e2b-latest.gguf`（3269 MB） |
| `qwen3.5:4b` | 已导入 `F:\WhaleGirlPetApp\models\qwen3.5-4b.gguf`（2526 MB） |

三个模型现在都能被扫描到。用引擎实跑 `qwen3.5-4b.gguf`：

```
backend = dafeiyu_cpp            （不经过 Ollama）
加载耗时 4.6 秒，health 正常
问「只回答两个字：你好」→ 答「你好」
```

（说明：`runtime\models` 里原来还有一份从 Ollama blob 复制的同名模型，和新导入的是同一份权重、只是文件名不同，两部分加起来多占约 5.7GB。数据目录那份是标准命名，想省空间可以删旧的，程序会自动用新的。）

### 3. 本地推理后端可手动指定

模型页顶部新增下拉框：

| 选项 | 含义 |
|---|---|
| 自动 | 有可用 Ollama 先用它，跑不动自动退回自带引擎（默认） |
| 只用自带引擎 dafeiyu | 完全不碰 Ollama，直接用 local gguf（推荐，你现在这台就适合这个） |
| 只用 Ollama | 强制走 Ollama，修好之前会报错 |

切完立刻停掉当前引擎，下一次对话按新后端走。

### 4. 云端功能没有动

云端 API（「AI 配置」里的 endpoint / model / api_key）一行没改；本地模型答不上来时仍然自动转云端（原逻辑保留）。这版只是多了一条「本地模型从哪来」的通道。
