## 1 代码审计：57 个模块 + 4 个真问题

新增 `tools/security_audit.py`（AST 静态扫 `app/` 全模块的危险调用）。初扫结果：6 条 medium、0 条"一看就炸"的高危。逐条人工核对后，命令执行全部是 `args` 列表 + 常量脚本，本地模型服务 `bind("127.0.0.1")`，都不构成远程可控。但挖到 4 个真问题：

1. **更新器"撒谎"**：`DownloadWorker` 只在 release 附带 `.sha256` 时才校验，而 `main._on_update_done` 无条件显示"已下载并校验通过"并直接 `startDetached` 安装。修法：只允许 https（http 仅放行 `127.0.0.1/localhost`）、`verified` 标志贯穿到底，未校验时按钮改成"仍要安装（不推荐）"+ 警告图标。
2. **`pending_cleanup.json` 路径穿越**：外部写一个 `..\..\` 的 name，桌宠下次启动就替它删目录。修法：name 必须是纯 basename、不含 `..`，且 `commonpath` 校验目标必须落在源目录内。
3. **账号 slug 穿越**：`accounts.json` 被改后 `account_dir()` 可能返回数据根，`accounts.delete` 的 `rmtree` 会打穿。修法：`_safe_slug()` 拒 `.`/`..`/非法字符，非法 slug 落到 `<root>/accounts/_invalid_slug`。
4. **配置写入非原子**：断电或杀进程会留下半截 JSON，全部设置丢失。修法：临时文件 + `fsync` + `os.replace`。

另加一层：maker「大肥鱼做小软件」的正则黑名单可被拼装绕过，新增 AST 检查（`os.system/popen`、`subprocess.*`、`ctypes.*`、`winreg.*`、`eval/exec/compile/__import__`、`shutil.rmtree/move`，并拦 `ctypes/winreg/telnetlib/ftplib/pty` 导入）。

复核：`tools/test_security_fixes.py` **29/29**；拼装写法 `__import__("o"+"s").system("calc")`、`getattr(__import__("os"),"sys"+"tem")` 实测均被拦。

## 5 进入速度匹配：Hermite 混合

原来用 smoothstep 交叉淡入（只保证位移连续，速度在两端仍有跳变）。现在对 `bob/rot/dx/dy` 四个通道做三次 Hermite：起点速度 = 旧动作当前速度，终点速度 = 新动作起始速度；缩放与透明度保持线性（避免过冲）；flip 取混合过半者。

窗口扫描（crab→hop，30fps）：

| mix | 切换位移 | 速度突变 |
|---|---|---|
| 0（硬切） | 16.46px | 15.20 |
| 0.15 | 0.20px | 10.30 |
| 0.22 | 0.12px | 3.97 |
| **0.30** | 0.71px | **1.14（−92%）** |
| 0.45 | 1.54px | 0.67 |
| 0.60 | 2.07px | 1.23 |

取 0.30：速度基本压平，位移代价只有 0.7px（肉眼在 30fps 下不可见）。`do_action` 默认 mix 0.30，队列衔接 0.25。复核 `tools/test_anim_mix.py` **12/12**。

## 6 隔离区 + 实时监控

- `app/quarantine.py`：先 `copy2` 到 `<sha前16位>_<净化名>.qtn`，核对哈希一致后再删原文件（中途失败不会两头空）；同名 `.json` 存 sha/size/原路径/时间/命中规则。恢复时原路径已存在就改放 `<名字>.restored.<ext>`，**绝不覆盖**。彻底删除只在用户点按钮时发生。
- `app/realtime.py`：只看下载 / TEMP / 启动文件夹里的 11 种可执行/脚本后缀，2 秒轮询一次，快照 `(mtime,size)` 比对；启动时先 `prime()` 记现状，不会把已有文件全报一遍。
- 接线：面板「隔离选中 / 打开隔离区」；托盘「实时监控新落地文件」（**默认关**，开了才后台跑）；命中 ≥30 分给气泡提示并推一条 `worried` 表情，只报不杀。

实测：单元 **24/24**（隔离/恢复/占用改名/删除/监控新增与改动/目录不存在）；单次快照 **0.2ms**；真机点击端到端通过。

## 7 EICAR 端到端：从"能力说明"变成可回归断言

之前的现象：两次跑出不同结果（一次自家规则命中，一次被 Defender 拦住读不到）。原因已定位：EICAR 落盘后 Defender 可能锁内容（`open` 抛 `Errno 22`），也可能直接删文件。

修法不是"绕过 Defender"，而是统一判定口径 —— 提取 `eicar_verdict(rule_match, hits, blocked, clean)`：

- 自家命中 → 检出；
- 系统锁住内容（errno 13/22）→ 检出（`blocked="system"`）；
- 系统直接删除（errno 2 或扫完文件已不在）→ 检出（`blocked="system-removed"`）；
- 其它错误、规则层没命中、无害对照被咬 → **不算通过**（防止把故障当能力）。

实测（授权真实触发 Defender）：**10 轮 10/10**，全部自家命中，p50 9.0ms；分支覆盖 **6/6**（含"系统锁内容""系统删除"两种当年真实出现过的路径）。结论：这条现在可以当稳定回归断言用了 —— 它断言的是"每次都能给出一个说得清的结论"，不是"每次都由自家规则抓到"。
