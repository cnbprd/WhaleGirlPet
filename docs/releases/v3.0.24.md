# v3.0.24（2026-11-26）

本版按 `anim.md` 的落地顺序做**第一阶段：动作导演接线**。不换素材、不加新渲染，
只把“谁来决定此刻播哪个动作、能不能抢”从各处调用里收回来。

## 做了什么

| 层 | 改动 | 结果 |
|---|---|---|
| 动作卡 | 新增 `app/director.py` 的 `Action`，一张卡描述 clip / 表情 / 优先级 / 时长 / 冷却 / 可打断 / then 接力；登记 15 张常用动作卡 | 加动作只改 `CARDS` 一行 |
| 仲裁 | `Director.submit()` 五档优先级：物理 100 > 用户 90 > LLM 70 > 自主 50 > 待机 30；同级不抢、先到先服务 | 自动动作抢不过用户动作 |
| 最短占用 | `min_hold_ms` 默认 120ms；hop 180ms、tumble 300ms | 鼠标扫过不再三动作各 60ms 抽搐 |
| 冷却 | 同一动作自主来源 6–8s 冷却；用户直点绕过冷却 | 自主碎碎念/动作不重复，用户连点仍然有反应 |
| 不可打断 | tumble 物理级、拖拽物理级；拖拽期间任何动作都被拒，松手释放 | 摔一半被拉去跳舞的情况消失 |
| 接力 | `then` 不再交给 Timeline 队列，改由 Director 在收回时按 50 级再仲裁一次 | 播完 A 自动接 B 也守优先级/冷却 |
| 收口 | `pet.do_action(..., source=user/llm/auto/chain)`；用户菜单/托盘/喂食走 90，随机表演走 50；打工持续态占 70，用户可接管；自主调度在用户/LLM 动作期间直接跳过 | 散落的 `do_action` 调用统一入口 |

## 实测

- `tools/verify_v324.py`：**26/26** 全过。
  - 纯仲裁：五档常量、同级不抢、min_hold 拦截与放行、摔跤锁定、冷却只拦自主、then 返回、拖拽锁。
  - 真实窗口：自动 hop 起播（50）；26ms 时用户 wave 被 min_hold 拒；170ms 后用户 wave 以 90 接管；tumble 以 100 起播并拒掉后续 hop；brawl 播完 2.6s 自动接 look；收尾回 idle。
- 性能：`submit + finish` 均值 **0.799µs/次**（20000 次 16.0ms），相对 33ms 帧预算可忽略。
- 版本：`3.0.24`（`app/paths.py` + iss 五处）。

## 刻意没做（留给下一阶段）

- 表情区域补丁、伪口型、说话态四通道叠加（文档第二阶段）。
- 裙摆/尾巴 alpha 遮罩分层 + Verlet spring（第三阶段）。
- 反馈 L0–L3 分级、泊松节流、thinking 占位动作（第四阶段）。
- 手感三天验收（第五阶段）；本版只保证调度正确，不冒充“看起来像活的”。

## 已知边界

- `do_walk` / `do_run` / `do_sleep` 这类“长时间状态”仍走原状态机，只加了“自主调度在用户/LLM 动作期间跳过”的闸；它们本身还没变成 Action 卡。
- 动作卡里的 `expr/bubble/sfx` 字段已留好，本版实际文案/表情仍由 `main.on_action` 和 `pet_window.do_action` 旧逻辑发，避免同一版同时改行为与文案。
- 用户被 min_hold 拒掉时没有视觉反馈（按文档口径：宁可少反应，不要抽搐）。
